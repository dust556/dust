# バックテスト — 何を測れて、何を測れないか

スクリーンが機能するかを判定するための基盤。**良い成績曲線を描くことが目的ではなく、
「ベンチマークとファクターとバイアスを差し引いた後に何か残るか」という
1つの問いに答えることが目的**である。

```sh
smallcap backtest \
  --universe-file universe.txt \
  --start 2015-01-01 --end 2025-12-31 \
  --benchmark IWM \
  --factors F-F_Research_Data_Factors.CSV \
  --ablation \
  --out bt/
```

---

## 仕組み

1. **リバランス日を生成する。** 既定は四半期ごと。スクリーンの入力は提出書類であり
   年4回しか更新されないため、それより速く回しても同じ数値を再売買してスプレッドを
   払うだけになる。
2. **各リバランス日にスクリーンを `--as-of` 付きで実行する。** その日までに
   提出されていた数値のみが使われる。
3. **通過銘柄をポートフォリオにする。** 既定は等金額。
4. **次のリバランス日まで保有し、リターンを計算する。**
5. **ベンチマーク・ファクターと比較する。**

### 報告ラグ (`--reporting-lag`)

12月期末の10-Kは1月1日には存在しない。既定では**期末から75日後**をリバランス日と
している（10-Qの提出期限は全区分で45日以内、10-Kは60〜90日）。

ラグを0にすれば成績は改善するが、その改善分は**実際には手に入らなかった情報**に
由来する。これはバックテストが意図せず「取引不可能」になる最も一般的な経路である。

### ルックアヘッドの遮断

スクリーンに渡されるデータは、提出書類も**株価も株式数も**すべて `as_of` 時点まで
巻き戻される。テスト `test_the_screen_is_only_ever_asked_for_the_rebalance_date` が、
スクリーン用のフェッチが未来の日付を伴わないことを検証している。

ポジション決済時のみ、リバランス日**以降**の株価を参照する（これは「既にエントリー
済みのポジションを手仕舞う」操作であり、銘柄選択には一切関与しない）。

---

## 除去できないバイアス — 全レポートの冒頭に必ず出力される

### 1. サバイバーシップバイアス（最大の問題）

銘柄ユニバースはプロバイダの**現在の**上場リストから来る。期間中に倒産・上場廃止・
買収された企業は**最初から存在しない**。失敗した企業はリストを去り、成功した企業は
残るため、**リターンは構造的に上方バイアスを持つ**。そしてこのバイアスは、
最も説得力があるように見える長期間のバックテストほど大きくなる。

唯一の解決策は、各リバランス日時点の上場リストを与えること:

```sh
smallcap backtest --universe-history universe_by_date.json ...
```

```json
{
  "2015-03-16": ["AAA", "BBB", "CCC"],
  "2015-06-14": ["AAA", "CCC", "DDD"]
}
```

これを与えない限り、レポートの先頭に警告が出続ける。

### 2. コスト未計上

リターンは**グロス**である。手数料・スプレッド・マーケットインパクトは一切
控除していない。**小型株ではスプレッドだけで、測定している超過リターンを
上回りうる**。時価総額5億ドル級の銘柄に数千万ドルを投じる場合、実効コストは
モデル化が困難であり、意図的に「0」ではなく「未計上」として扱っている。

### 3. 上場廃止銘柄の決済価格 (`--missing-price-policy`)

期末に株価が取得できないポジションの扱い。これはバックテストが静かに嘘をつく
典型的な箇所である。

| ポリシー | 挙動 | バイアスの向き |
|---|---|---|
| `drop` (既定) | 除外して残りで再正規化 | **上方**（上場廃止は失敗に偏るため） |
| `zero` | 全損として扱う | 下方（悲観的な下限） |
| `flat` | 変化なしとして扱う | 中立だが非現実的 |

どのポリシーも何らかのバイアスを持つため、**選択は明示的**であり、該当した
ポジション数は毎回レポートに出力される。`drop` で良い成績が出た場合は、
必ず `zero` で下限を確認すること。

#### この差は小さくない

同梱フィクスチャには、2024年9月に株価系列が途絶える銘柄 `DELISTED` を
含めてある。ポリシーだけを変えて同じバックテストを回すと:

| ポリシー | CAGR | ベンチマーク比 |
|---|---:|---:|
| `drop` | **+17.07%** | +2.54% |
| `flat` | +16.40% | +1.87% |
| `zero` | **−1.55%** | **−16.09%** |

**戦略もデータも同一で、違いは上場廃止銘柄の決済方法だけである。**
それが「市場を上回る戦略」と「損失を出す戦略」を分けている。
実データではこの差はさらに大きくなりうる。

#### 陳腐化した最終気配値という罠

上場廃止された銘柄は、株価系列が「欠損」するのではなく**更新が止まる**。
素朴に「決済日以前の最新の終値」を引くと、**最終取引価格が永久に返り続け**、
ポジションは毎期その価格で「決済」されたことになる。欠損として検知されない。

本エンジンはエントリー価格だけでなく**決済価格にも陳腐化チェック**を掛けており
(`max_price_staleness_days`、既定10日)、これを超えて古い気配値は
「決済価格なし」として上記のポリシーに回される。このチェックがないと
`--missing-price-policy` は一度も発火せず、実質 `flat` で固定される。

### 4. サンプルサイズ

四半期リバランスでは年4観測しかない。10年で40観測。
**20観測未満の場合、レポートは「統計量は記述的であって証拠ではない」と明記する。**
また平均保有銘柄数が5未満の場合も警告を出す（その成績は
スクリーンではなく数銘柄の固有リスクが生んでいる）。

## ファクター調整 — なぜ生リターンでは不十分か

**小型株スクリーンがベンチマークを上回るのは当然である。** サイズファクターに
エクスポージャーを取るよう設計されているのだから、小型株が良い年には必ず勝つ。
それは戦略の価値ではなく、リスクプレミアムの受け取りにすぎない。

`--factors` にKen Frenchのデータライブラリの
`F-F_Research_Data_Factors` (monthly) を渡すと、超過リターンを
Mkt-RF / SMB / HML に回帰し、**そのエクスポージャーの対価を支払った後に
残るもの**（アルファ）を算出する。

```
超過リターン = α + β_mkt·(Mkt-RF) + β_smb·SMB + β_hml·HML + ε
```

- 月次データは各リバランス期間に複利で集約される
- 期間が月次データで完全にカバーされない場合、その期間は**回帰から除外される**
  （部分的なカバレッジはファクターエクスポージャーを過小評価し、アルファを
  過大評価するため）
- パーセント表記と小数表記は自動判別され、どちらと解釈したかをレポートに出力する
- **t値は残差の独立・等分散を仮定している。** 期間リターンに自己相関があれば
  楽観的な値になる。レポートに毎回明記される

自動ダウンロードは実装していない。研究結果は「後から読み直せるファイル」に
依存すべきであって、「実行日にURLが返したもの」に依存すべきではない。

## 条件アブレーション (`--ablation`)

5条件を1つずつ外して全体を再実行する。

| 結果 | 解釈 |
|---|---|
| 外すと成績が悪化 | その条件は機能している |
| 外しても**変化なし** | このサンプルでその条件は何も仕事をしていない |
| 外すと**改善** | その条件はコストになっている |

条件を擁護する前に、それが実際に効いているかを確認するための機能である。
同梱フィクスチャでの実行例では、レバレッジ条件を外しても結果が1ベーシス
ポイントも動かない。

---

## 結果の読み方

優先順位は以下の通り。上から順に、それを通過しなければ下を見る意味がない。

1. **バイアス欄**（サバイバーシップ、コスト、サンプル数）
2. **平均保有銘柄数** — 1〜3銘柄なら、それはスクリーンの成績ではない
3. **アブレーション** — どの条件が効いているか
4. **ファクター調整後アルファとそのt値** — 生リターンではなくこちら
5. 生の CAGR

CAGRを最初に見て、バイアス欄を読まずに結論を出すことが、
バックテストの最も一般的な誤用である。レポートがバイアス欄を先頭に置いているのは
そのためである。

---

## このバックテストが証明しないこと

- 将来のリターン
- 取引コスト控除後に残るか
- 上場廃止銘柄を含めた場合にも残るか（ユニバース履歴を与えない限り）
- 閾値を少し変えても残るか（感応度は `--set` で自分で確認すること）

**バックテストは、1つの歴史の上で、コスト控除前に、失敗した企業を除いた
ユニバースに対して、あるルールが生んだであろう数値を測定するものである。
過去についての証拠であり、将来についてはごく弱い証拠にすぎない。**
