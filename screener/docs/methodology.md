# 算出方法と既知の限界 (Methodology and known limitations)

本エンジンが各条件をどう数値化しているか、そしてその数値が**何を証明せず、
何を見落とすか**を記述する。スクリーニングの結果よりも、この文書のほうが
実務上は重要である。

---

## 条件① 時価総額 5〜30億ドル

**計算**: `時価総額 = 株価 × 発行済株式数`

- 発行済株式数: SEC XBRL の `dei:EntityCommonStockSharesOutstanding`
  (10-K / 10-Q 表紙の数値)。取得できない場合は
  `us-gaap:CommonStockSharesOutstanding` に後退する。
- 株価: `--prices-dir` のローカル CSV、または Stooq の日次終値。

**限界**

| 項目 | 内容 |
|---|---|
| 表紙株式数の遅延 | 表紙の株式数は提出日時点であり、四半期内の自社株買い・増資を反映しない。`market_cap.shares_max_age_days` を超えると警告を出す。 |
| 複数株式クラス | A株・B株を持つ企業では、表紙の数値がどのクラスを含むかが filer によって異なる。デュアルクラス企業の時価総額は過小評価されうる。 |
| カバレッジの代理指標 | 本条件が実際に検証しているのは**時価総額のみ**である。Fama-French の議論の核心である「アナリストカバレッジの薄さ」は、無料データソースに存在しないため検証されていない。30億ドル以下であってもカバレッジが厚い銘柄は存在する。 |

## 条件② 粗利率40%以上、かつ改善傾向

**計算**

```
粗利率 = 売上総利益 / 売上高
トレンド = 年次粗利率に対する OLS 回帰の傾き (年あたりの粗利率ポイント)
直近変化 = 直近TTM粗利率 − 1年前TTM粗利率
```

3つすべてを満たす場合のみ PASS とする (水準・傾き・直近変化)。
Novy-Marx 本来の指標である粗利/総資産 (gross profits-to-assets) も併記するが、
ゲートには使わない。両者は資産集約型企業で逆方向を示すことがある。

**限界**

| 項目 | 内容 |
|---|---|
| **会計上の組み替え** | これが最大の弱点である。売上原価からサポート費用を販管費へ組み替えるだけで粗利率は上昇する。XBRL 上、実体的な改善と区別できない。`--ai` レイヤーはまさにこの対立仮説を列挙させるために存在する。 |
| 買収による混合 | 高粗利企業を買収すれば連結粗利率は上がる。本エンジンは organic / inorganic を分離しない。 |
| 業種間比較の無意味さ | 40%という水準は業種横断では意味を持たない。ソフトウェアでは低く、流通では極めて高い。セクター相対で運用する場合は `--set gross_margin.min_level=...` を業種別に変える必要がある。 |
| GrossProfit 未タグ | 多くの filer は `GrossProfit` をタグ付けしない。その場合は `売上高 − 売上原価` で導出する。売上原価の定義は filer 依存である。 |

## 条件③ ROIC > 資本コスト、かつ再投資率が高い

**計算**

```
NOPAT          = 営業利益 × (1 − 実効税率)
投下資本        = 有利子負債 + 自己資本 − 現金及び短期投資
ROIC           = NOPAT / 期中平均投下資本
再投資額        = (設備投資 − 減価償却) + 運転資本増減 + 買収支出
再投資率        = 再投資額 / NOPAT
内在成長率      = ROIC × 再投資率          ← Mauboussin の恒等式
WACC           = E/V·(rf + β·ERP + 小型株プレミアム) + D/V·rd·(1−t)
```

デフォルトでは直近3期の平均を用いる。単年度の設備投資や買収は再投資率を
閾値以上に振れさせるためである。

**限界**

| 項目 | 内容 |
|---|---|
| 余剰現金の定義 | 現金を**全額**非事業資産として投下資本から控除している。現金比率の高い小型株では ROIC が高めに出る。売上高の数%を運転現金として残す方式もあるが、その水準自体が恣意的である。現金残高は常にレポートに併記する。 |
| のれん | 投下資本にのれんを含めている (自己資本経由)。買収を繰り返した企業の ROIC は、のれん控除後ベースより低く出る。これは意図的である (支払った価格を含めた資本効率を見る)。 |
| ベータ推定 | 週次リターンの OLS。小型株は非同期取引によりベータが下方に歪むため日次を避けた。価格履歴が不足する場合は `returns.default_beta` (1.20) に後退し、その旨を reasons に明示する。 |
| 小型株プレミアム | CAPM に 2% の小型株プレミアムを加算している。教科書的な CAPM には存在しない項である。これを入れないと、サイズ要因こそが超過収益の源泉であるはずの銘柄群が、そのリスクを無償で享受しているように見えてしまう。`returns.size_premium=0` で無効化できる。 |
| リース債務 | 投下資本・有利子負債ともにオペレーティングリース債務を除外している (条件④と同じ理由)。 |
| 将来の再投資機会 | 過去の再投資率は測定できるが、**今後も同じ利回りで再投資できるか**は測定できない。Mauboussin の議論の核心はそこにあり、本エンジンはそこを検証していない。 |

## 条件④ 有利子負債 / EBITDA 3倍以下

**計算**: `(短期借入金 + 長期借入金) / (営業利益 + 減価償却費)`

**設計上の判断**

- **グロス債務を使用** (ネット債務ではない)。原文が「有利子負債」を指定しているため。
  現金は使途変更・拘束・海外子会社への滞留がありうるが、債務は消えない。
  ネット債務も常に併記し、`leverage.use_net_debt=true` でゲート側も切り替え可能。
- **調整前 EBITDA を使用**。「調整後 EBITDA」の加算項目は経営陣の主観であり、
  レバレッジ検証の場で受け入れるべきものではない。
- 無借金企業は自明に PASS とし、その旨を明記する。
- 有利子負債があり EBITDA が非正の企業は `INSUFFICIENT_DATA` ではなく **FAIL** とする
  (比率は計算できないが、条件を満たしていないことは明白であるため)。

**限界**

| 項目 | 内容 |
|---|---|
| オペレーティングリース | ASC 842 上は負債だが除外している。含めると「不動産を借りている企業」が一律に不利になり、本条件が狙う財務脆弱性とは別物を測ることになる。資産をリースで賄う業態では過小評価となる。 |
| 減価償却費の未タグ | キャッシュフロー計算書項目のため未タグの場合がある。その際は EBITDA = 営業利益 として扱う。これは EBITDA の過小評価 = 判定の厳格化であり、誤差の方向としては保守的である。 |
| 期末時点のみ | 期末残高で評価するため、期中のレバレッジのピークを捉えない。 |

## 条件⑤ 経営陣の持株比率 10%以上

**これは本エンジンで最もデータ品質が低い条件である。**

**計算**: SEC Form 3/4/5 (内部者報告書) の XML を解析し、
各内部者・各保有形態 (直接/間接) ごとに**最新の
`sharesOwnedFollowingTransaction`** を取得して合算し、発行済株式数で除す。

デフォルトでは役員・取締役のみを対象とし、外部の10%超保有者は除外する。
Jensen-Meckling の議論は「経営者の利害一致」であって、株主構成の集中度ではないため。

**限界 — 必読**

| 項目 | 内容 |
|---|---|
| **下限値である** | 算出値は真の内部者持株比率の**下方バイアスのかかった推定**である。Form 3 提出後に一度も取引していない内部者、委任状でのみ開示される保有ビークル、未行使オプションは捕捉されない。 |
| 権威あるソースは DEF 14A | 正しい数値は年次委任状 (DEF 14A) の beneficial ownership 表にある。これは HTML の散文でありタグ付けされていないため、本エンジンは解析していない。 |
| 近接判定 | 閾値の3%以内で不合格となった銘柄は `NEAR MISS` として明示的に警告する。この下限値ベースで自動的に切り捨てるべきではなく、委任状を人間が確認すべきである。 |
| 保有形態の重複計上 | 同一株式が複数の内部者によって間接保有として報告される場合 (共同支配のファミリートラスト等)、重複計上されうる。逆方向の誤差である。 |
| 提出件数の上限 | 既定では直近120件の内部者報告書までを走査する。提出の多い企業では古い保有が欠落する。 |

## 横断的な設計判断

### `INSUFFICIENT_DATA` と `FAIL` の区別

これは本エンジンの中核的な設計判断である。データが無いことは、条件を
満たさないことと**同じではない**。両者を混同すると、開示の薄い企業が
「不合格」として静かに消え、その理由が誰にも見えなくなる。

- データ欠損 → `INSUFFICIENT_DATA` (スコアに算入せず、重みを分母から除去)
- `data_quality` が `scoring.min_data_quality` 未満の銘柄はランキング対象外
- レポートには条件別の「判定不能件数」を必ず出力する。
  **この件数が多い場合、それは企業についての発見ではなくデータ網羅性の問題である。**

### ポイントインタイム (`--as-of`)

XBRL の各ファクトは提出日 (`filed`) を持つ。`--as-of` を指定すると、
その日までに**公開されていた**数値のみを使用する。同一期間に複数の提出が
ある場合 (当初の 10-Q と後の 10-K による修正再表示)、as-of 時点で公開済みの
うち最新のものを採用する。

これは過去日付での検証を行う際に必須である。修正再表示後の数値で過去を
スクリーニングすれば、実際には取引できなかった結果が得られる。

### 再現性

- コア部分は標準ライブラリのみに依存する (依存パッケージのドリフトを避けるため)
- HTTP レスポンスはディスクにキャッシュされる。`--offline` でキャッシュのみを使用
- `smallcap dump-fixture` でライブ取得結果をフィクスチャとして固定できる
- 設定内容は `results.json` にそのまま出力されるため、実行条件を後から再現できる

### AI レイヤー (`--ai`) の位置づけ

Claude による定性レビューは**判定を一切変更しない**。スコアにもランキングにも
影響しない。付随するコメントであり、レポート上は常に「LLM 生成・未検証」と
ラベル付けされる。`--ai` の有無で銘柄の合否は完全に同一である。

このレイヤーの唯一の価値は、**数値が示す解釈に対する対立仮説を列挙させること**に
ある (上記の「会計上の組み替え」など)。

## 本エンジンが答えられない問い

- バリュエーションが妥当か (本スクリーンは価格を時価総額算出にしか使わない)
- 粗利率の改善が持続するか
- 経営陣が有能か
- 産業構造が今後も有利か
- 開示が正直か

5条件をすべて満たすことは、**調査を始める理由**であって、調査の結論ではない。
